# Cloudflare R2: medios del sitio

El bucket público no productivo ya existe y contiene los doce medios del inventario. `r2.dev` se usa sólo en desarrollo/staging; producción necesita bucket y hostname separados. R2 no requiere credenciales de escritura en la aplicación: la carga del MVP es manual.

## Cómo se resuelven las imágenes

PostgreSQL guarda claves relativas estables, como `images/catalog/calios-product.png`. Frontend y backend forman la URL con `MEDIA_BASE_URL`. Stripe Checkout no puede acceder al origen LAN: para incluir las imágenes en su vista usa `STRIPE_MEDIA_BASE_URL`, una URL HTTPS pública sin barra final. El backend agrega la clave `image_key`; las imágenes de carrito y Stripe son las variantes `*-product.png`, no `*-lifestyle.png`.

El origen público de desarrollo es:

```text
https://pub-47df7d3a7dd94d268c1661b2c36e0ae5.r2.dev
```

En desarrollo normal, Compose usa el origen local configurado en `.env`. Para probar R2, establece la URL pública como `MEDIA_BASE_URL` en frontend/backend y como `STRIPE_MEDIA_BASE_URL` para Stripe. No guardes tokens ni credenciales de R2 en el repositorio.

## Separación por entorno

- Mantén el bucket actual para desarrollo/staging y crea otro para producción.
- En producción, usa un dominio personalizado para los medios; `r2.dev` no es un hostname de producción.
- Conserva las claves del inventario al reemplazar imágenes para evitar cambios en la base de datos y el código.
- No agregues escritura desde frontend/backend mientras la carga siga siendo manual.

Consulta [precios y cuotas](https://developers.cloudflare.com/r2/pricing/) al preparar una cuenta o cambiar de plan y revisa el [mapa de implementación](implementacion.md) para DNS/TLS.
